# Linux System Administration Labs

A practical engineering portfolio focused on Linux system administration, infrastructure fundamentals, networking, and troubleshooting.

This repository documents hands-on technical work, structured experiments, diagnostic procedures, and lessons learned while developing Linux administration skills.

## Focus Areas

| Area                  | Topics                                                      |
|-----------------------|-------------------------------------------------------------|
| Linux Fundamentals    | Filesystem hierarchy, processes, users, groups, permissions |
| System Administration | systemd, storage, filesystems, devices, logs                |
| Linux Internals       | `/proc`, `/sys`, `/dev`, kernel interfaces                  |
| Networking            | Network configuration, DNS, connectivity diagnostics        |
| Troubleshooting       | Evidence collection, hypothesis testing, root cause analysis|

## Engineering Approach

Technical problems are approached through a structured diagnostic workflow:

1. **Incident** — define the problem and its scope.
2. **Observation** — identify symptoms and collect initial information.
3. **Facts** — separate verified evidence from assumptions.
4. **Hypotheses** — formulate technically plausible explanations.
5. **Testing** — perform controlled diagnostic checks.
6. **Evidence** — interpret command output and system behavior.
7. **Root Cause** — identify the underlying failure.
8. **Resolution** — apply an appropriate corrective action.
9. **Verification** — confirm that the system behaves as expected.

## Lab Documentation Standards

Each practical lab aims to document:

- Objective and technical background
- Environment and prerequisites
- Commands and their options
- Expected and observed behavior
- Evidence and technical interpretation
- Failure scenarios and troubleshooting
- Resolution and verification
- Lessons learned
